每讲做什么、交什么

第 1 讲：数据探索与首个模型

上游入口：Intro to Machine Learning：Basic Data Exploration / Your First Machine Learning Model

操作：列出 X、y、输入形状；找出 fit 与 predict；运行本课 digits 基线。

产物：任务规格 + 一条 AI 代码审查记录。

本地配套：01-digits-workflow.ipynb

第 2 讲：验证与模型复杂度

上游入口：Intro to Machine Learning：Model Validation / Underfitting and Overfitting

操作：固定开发划分，比较树的叶节点数量；记录训练 MAE 与验证 MAE。先用本课多项式实验理解同一现象。

产物：复杂度—误差表；解释为什么不是越复杂越好。

本地配套：02-underfitting-overfitting-sklearn.ipynb

第 3 讲：Titanic 分类与指标

上游入口：Titanic 比赛：Data 与 Code

操作：查看字段含义，在有标签训练表内部划分；先运行多数类基线，再运行 Logistic；比较混淆矩阵。

产物：说明正类、漏检与误报；测试表无标签不能计算本地准确率。

本地配套：03-classifier-comparison.ipynb

第 4 讲：Pipeline、CV 与泄漏

上游入口：Intermediate Machine Learning：Pipelines / Cross-Validation / Data Leakage

操作：先阅读教程再做练习；画出每折填补器、编码器和模型的 fit 范围；审查预测时点不可用字段。

产物：字段审查表 + 泄漏修复前后结果；解释分数下降。

本地配套：04-evaluation-leakage.ipynb

第 5 讲：缺失值、类别与集成

上游入口：Intermediate Machine Learning：Missing Values / Categorical Variables；Intro：Random Forests

操作：在同一验证划分比较 Dummy、Logistic 与森林；先完成填补和编码，再改变一个树参数。

产物：模型比较表 + 一次受控改进；保留失败结果。

本地配套：05b-titanic-mixed-types.ipynb

第 6 讲：增加一个核方法基线

上游入口：沿用 Titanic 的同一开发协议，属于本课程扩展

操作：将 StandardScaler 与 SVC 放入 Pipeline；仅在开发 CV 搜索 C 与 gamma；记录时间。

产物：质量、成本和尺度变化的解释；不以榜单决定参数。

本地配套：06-svm-kernels.ipynb

第 7 讲：阅读社区文本案例

上游入口：Kaggle Code 社区检索 sentiment classification；HF 模型卡为主

操作：先核对数据与模型训练来源，再比较 TF-IDF 与预训练方案；记录样本量、版本与算力。

产物：一张资源差异表和真实错例。不要求本讲参与比赛。

本地配套：07-hf-pretrained-comparison.ipynb

第 8 讲：复现、改进与报告

上游入口：Titanic 或 House Prices；后者为选做回归任务

操作：记录作者、原链接、版本与许可；保留基线、固定验证、一次改进，按官方样例准备提交文件。

产物：可复现 Notebook + 来源清单 + 实验表 + 错例。上传比赛不是必需项。

本地配套：08-project-audit.ipynb

Titanic：从官方页面到可检查的实验

  1. 打开比赛 Overview、Data、Rules，了解目标、字段和使用条件。在 Code 中选择讲清楚划分和预处理的入门 Notebook；记录作者、URL、版本、访问日期及可见许可。不是选择榜单最高的代码。
  2. 在平台复制并运行所选 Notebook，先不修改模型。逐项标记数据加载、特征、标签、划分、fit、predict、评价与导出单元。不能解释的数据处理先查文档。
  3. 在 train.csv 中保留本地验证集；在任何填补、编码、特征选择之前划分。所有模型复用相同划分。比赛 test.csv 只用于生成最终预测。
  4. 建立 Dummy 基线。将数字填补、类别编码和 Logistic 组成 Pipeline，再与树模型比较。记录随机种子、指标、参数、耗时；只用开发集决定方案。
  5. 做一次受控改进：只改树深，或只替换模型。报告改善、无变化或下降，均需解释。最后读至少三个真实错例。
  6. 若选择参赛，冻结方案后在全部比赛训练数据重训，对 test.csv 预测，按 sample_submission.csv 检查列名、行数、ID 顺序与标签取值，再自行上传。不要根据公共榜单反复改动本地测试结论。

离线替代与答案要点

本地 05b Notebook 使用 OpenML 40945 的 Titanic 数据缓存，字段为 age、fare、embarked、sex、pclass。它与 Kaggle 比赛的 train/test 不是同一划分；不要拼接两个版本或将本地分数写成比赛成绩。它可直接用于练习填补、编码、Pipeline、CV 和模型比较。

  • 训练高分、验证低分：可能拟合训练细节；还要检查划分和分布，不能只凭一个分数归因。
  • 填补后出现高分：检查填补与特征选择是否提前看过验证数据；Pipeline 需在每折内 fit。
  • 复杂模型不如基线：先核对标签映射、划分和指标，再看表示、样本量与复杂度，不能删掉结果。
  • 排行榜高分：只说明该评测反馈下表现好，不证明新时间、新人群或现实业务一定可靠。
