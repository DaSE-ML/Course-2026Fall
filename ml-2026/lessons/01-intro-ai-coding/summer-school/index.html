所以，Vibe Coding 到底改变了什么？

从解题者到出题者

它让你更早从
“解题者”变成
“出题者”。

以前常常是：先学很久，才有资格做一个作品。现在可以先做一个小原型，再在做的过程中发现：真正的问题是什么？谁会用？它到底好不好？

不变的是什么？

“与其预测什么会变，不如关注什么不变。”— Morgan Housel · Same as Ever

技术栈 3 年一换，但这些能力永远不会过时：

🔍
发现问题

观察、思考、提出好问题

🎨
设计方案

架构思维、系统设计

🧭
判断能力

知道什么是好的、什么是对的

4 DAYS / 课程不是工具体验营

四天里，我们用一个项目，
练这三种能力。

DAY 1看见问题

从生活、校园或兴趣里，找到一个真实的切口。

DAY 2做出第一版

把想法变成可运行、可以讨论的原型。

DAY 3一起改好它

协作、复核、取舍，让作品更像一个真正的产品。

DAY 4讲清楚它

演示你们做了什么，也诚实说明还没解决什么。

FINAL CHALLENGE / 像一个开源项目那样工作

最后，你们要做的不是

BEFORE WE BUILD / 先把入口准备好

不把环境问题，
误会成能力问题。

全员必做注册 GitHub，带电脑和电源，能打开课程材料。
核心准备安装 Claude Code CLI 与 Git；能完成的同学先验证版本与启动。
可选进阶OmniRoute、CC Switch、Codex app、Tavily 等，后续按课程说明使用。
扫描二维码，填写 GitHub 信息

用于后续批量邀请加入课程 GitHub Organization。

TEAM DESIGN / 分组规则

4–5

每组 4–5 人，1 位组长

组长负责推进沟通与节奏，不是唯一写代码的人。我们会按兴趣、经验与角色意愿尽量做互补分组。

今天说明分组方式；名单与后续组内沟通安排将另行发布。

01问题与体验用户、需求、页面与演示
02方案与计划任务拆分、资料与协作推进
03实现与集成功能、运行、连接与修改
04检验与改进测试、复核、反馈与记录
05每个人都是 contributor不要求每个人都会写代码；但每个人都应推动作品往前走。

ONE LAST THING
